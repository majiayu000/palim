# 设计实现与验证结果

日期：2026-09-30。库位于本目录，包名 `jsondiffpatch-rs` 0.1.0，尚未发布。

## 已实现的范围

完成 [DESIGN.md](DESIGN.md) 的 JSON 核心能力：全部 JSON 类型的比较、对象过滤、数组身份匹配、多项移动及移动后的字段修改、完整旧值 delta、序列化、patch/reverse/unpatch、Unicode 多段文本差异、ForwardDelta，以及 RFC 6902 导出和六种标准操作应用。

实现决策是复用 imara-diff 的序列匹配和 json-patch 的标准补丁器，重写 JSON/delta 算法；不承接旧 Rust 移植的全局配置和未完成 reverse。原型代码保留在相邻评估目录，本库是独立 Cargo 包。

## 正确性证据

| 检查 | 实际结果 |
|---|---|
| Rust 固定回归 | 9 个测试通过，含复杂移动、过滤、错误基线、Unicode、深度、JSON Patch 原子错误 |
| 保存的文档对 | 373/373 通过正向、逆向、serde 和独立 RFC 应用验证 |
| 公开 RFC 6902 测试 | 92 个启用的正常/错误用例通过；遵循上游 disabled 标记 |
| 属性检查 | 4 类各 2,048 次，共 8,192 次，固定种子 20260930，另保留历史失败种子 |
| Rust delta → JS | 1,073/1,073 正向通过 |
| Rust inverse → JS | 1,073/1,073 还原源文档 |
| Rust RFC → 独立 JS 应用器 | 1,073/1,073 正向通过 |
| JS 原 delta → Rust | 1,073/1,073 正向和 Rust 生成的逆向通过 |
| 文档示例 | 1 个 Rust doctest 通过 |

属性测试分别覆盖递归任意 JSON（含浮点和大整数）、重复身份的数组混合变更、任意合法 Unicode 文本和外部 delta 的拒绝/错误处理。随机检查不等于证明所有可能输入；重复 ID 的语义为确定性配对，不保证最小补丁。

互操作用例包含原 373 对、600 对随机重复身份对象数组和 100 对多语言/emoji 文本。所用上游为 jsondiffpatch 0.7.6、@dmsnell/diff-match-patch 1.1.0、fast-json-patch 3.1.1；完整输入、双方 delta、检查和摘要保存在 `results/`。

这批复杂用例中，上游 JS 自己的 reverse 只还原 566/1,073。其余 507 例主要是复杂数组重排，另有 6 例文本。它们单独记录在 [interop-summary.json](results/interop-summary.json) 的 `upstream_inverse_failures`，没有把错误结果当作 Rust 的期望值。Rust 必须依据原始 delta 正确撤销，并通过独立 JS 应用器；本轮全部通过。这里的数字仅描述当前固定测试集，不代表上游在所有用户负载中的失败率。

本轮实际修复并回归的边界包括 f64 精确往返、复杂 RFC 移动排序、文本重叠上下文的撤销顺序、JS surrogate 修复后的长度偏差，以及近深度上限 delta 的默认 serde 读取。

## Benchmark 方法

Apple M2 Max，Node 24.14.0，Rust 1.97.0，release 编译。机器、版本和输入 SHA-256 见 [benchmark-environment.json](results/benchmark-environment.json)。

1. **Criterion**：14 种输入、38 个 diff/patch/reverse 测量，各 20 样本，100 ms 预热、至少 300 ms 采样、5,000 次重采样。保存估计值、95% 置信区间及原始样本到 [criterion.json](results/criterion.json)。整轮完成后，文本裁剪优化仅重测受影响的 3 项。
2. **JS 对照**：20 种相同 JSON 输入，36 组实测、4 组明确跳过。两边预热 20 次，按一次测量校准 1–200 次迭代/样本，取 5 样本中位数。每个实现/输入在独立进程中顺序测量；本轮最终对照期间没有并行运行编译或其它 benchmark。
3. **主指标 `pipeline_ms`**：JSON 解析 → diff → delta JSON 序列化，保留完整旧值；两边均支持撤销。文件读取、进程启动、应用和逆向不计入该指标。另记录已解析 Value 的 diff、应用和逆向时间。
4. **RSS**：整个进程峰值，包含运行时、文档、预热、正确性验证和迭代，不能解释成算法自身的分配量。JS 应用阶段还克隆 delta，以避免上游对补丁的修改，故 `patch_ms` 也不能隔离成语言速度差。
5. Criterion 用数字数组和简化身份对象；JS 对照用字符串数组、较丰富身份对象和固定真实元数据。两套输入不同，不把它们的计时混在一起比较。

4 组跳过为 JS 的 20,000 项移位、逆序、全异和稀疏修改，其二维 LCS 分配超出本次预算。未执行即标为 skipped；没有将跳过当作超时、错误或 Rust 胜出。

## 主要对照结果

单位 ms。补丁大小是未压缩 JSON 的 UTF-8 字节数。

| 输入 | JS pipeline | Rust pipeline | JS / Rust 补丁大小 |
|---|---:|---:|---:|
| 小配置改一项 | 0.0063 | 0.0120 | 28 / 28 B |
| 2,000 项，头部插入 | 0.2731 | 0.4238 | 22 / 22 B |
| 2,000 项，末项移到头部 | 43.3850 | **0.4352** | 27 / 27 B |
| 2,000 个带 ID 对象，移动和字段修改 | 80.4370 | **2.2307** | 74 / 74 B |
| 固定 crates.io 元数据 100 项，移动和修改 | 1.0088 | 0.7749 | 141 / 141 B |
| 20,000 项，末项移到头部 | 未测 | **4.4129** | — / 28 B |
| 长 ASCII 文本，小幅插入 | **0.3013** | 1.0407 | 83 / 56 B |
| 长 Unicode 文本，小幅插入 | **0.3148** | 0.9545 | 151 / 56 B |

2,000 项移位约快 **99.7 倍**，身份对象用例约快 **36.1 倍**。本轮是完整可撤销 delta 的对照，同两例的输出大小一致，解决了前一版原型格式和功能不等价的问题。

收益来自匹配算法和实现方式的改变，不能归因于 Rust 语言本身。小文档、普通插入和长文本没有稳定优势。文本公共前后缀裁剪将 Criterion 的该样本 diff 从约 1.093 ms 降到约 0.468 ms，但对照的长文本 pipeline 仍比 JS 慢约 3 倍。

真实元数据的原始文档来自公开 crates.io API 的固定快照；移动和描述更新是人工控制的修改。这不是线上用户请求采样。库的下游采用需求和其它 CPU/操作系统性能尚未验证。

完整 36 组结果、5 个样本和 RSS 见 [comparison.json](results/comparison.json)。不以单个最高倍率概括整个库。

## 交付边界

- 交付 JSON 核心库、公开 API 文档、完整设计、测试、互操作脚本和 benchmark。未发布、未提交到远端。
- 文本应用严格校验位置和上下文，具有与 JS 模糊匹配不同的错误语义。
- 默认文档深度 128；delta 含协议包装，最大 127。近边界输入可返回明确深度错误。
- JSON 无 absent root，根删除返回错误；两个现有文档间的根替换支持撤销。
- Histogram 不保证最小 LCS；JSON Patch 的复杂重排导出可能产生额外移动并承担顺序数组操作成本。
- JS 的 Date/undefined/functions、HTML/CSS 展示、产品 CLI 和语言绑定不在这个 JSON 基础库中。

复现命令见 [README.md](README.md)。上游测试来源和许可证见 `tests/fixtures/NOTICE.md`。本地 Cargo 包的源码和测试不依赖 Node 或相邻评估项目。
